# Рабочие материалы DSH-MyWork

Эта папка **отслеживается Git** с 2026-10-03 (решение владельца, дефект R-54: корпус плана — вход гейта `pnpm run check:plan`, а игнорируемый корпус оставлял корпусную половину этого гейта недостижимой вне машины автора). Здесь лежат исходный архитектурный план, декомпозиция, карточки DSH Task Board и отчёты. Это материалы разработки плагина; runtime-данные самого плагина должны храниться вне репозитория согласно §7 архитектуры. Репозиторий публичный, поэтому здесь не должно быть секретов, ключей и содержимого живого профиля.

- `architecture/DSH-My-Work-Architecture-v0.1.md` — неизменённая копия пользовательского плана.
- `architecture/DSH-My-Work-Architecture-v0.2-decisions.md` — ADR016…ADR028, проекция девяти зон доски, стратегия Beads и границы интеграции с DSH. Аддитивен к v0.1.
- `EXECUTION-PLAN.md` — **исторический** execution plan v0.2; текущую работу из него не начинать. Канон исполнения — `plan-v0.3/01-MASTER-PLAN.md` §1.4, §16–§18 и фактический `main`.
- `tasks/tasks.json` — структурированные определения 55 задач и DAG зависимостей (кроме `adrs` — ADR, которые карточка обязана прочитать).
- `tasks/MW-*.md` — отдельные задания с готовым prompt. Карточки со статусом `superseded` начинаются с запрета на исполнение и не запускаются.
- `tasks/INDEX.md` — оглавление по этапам, критический путь и статусы; регенерируется вместе с `tasks.json`.
- `tasks/board-actions.json` — точные операции создания/перемещения карточек, UUID и requestId (v0.1, только для legacy-доски).
- `tasks/board-export.json` — подтверждённый снимок созданных карточек из DSH (v0.1).
- `reports/` — результаты задач: commit/diff, проверки, ограничения и ссылки на evidence.

Все карточки используют workspace `H:\Repo\DSH-MyWork` и модель `opencode-go/deepseek-v4.1-flash`. Ничего не запускается автоматически. Доска создаёт отдельную сессию при ручном запуске: привязка к workspace не означает продолжение одной длинной беседы.

Инструкция «начать с MW-001, затем MW-002» относится к историческому плану v0.2 и больше не задаёт текущую точку старта. Для новой работы сначала проверить фактический `main`, затем `plan-v0.3/01-MASTER-PLAN.md` §1.4 и §16–§18. Статус карточки сам по себе не доказывает приёмку: нужны проверки, evidence и независимое review для изменения кода.

DSH Task Board сейчас не предоставляет поля DAG зависимостей: они сохранены в JSON, описании и prompt каждой карточки. Их проверяет исполнитель перед началом; автоматическую блокировку этой доски не заявляем. В JSON исходный статус `planned` фиксирует декомпозицию, а текущие статусы исполнения принадлежат DSH. Не править живой ledger напрямую.

### Набор задач v0.2

В наборе 55 карточек. MW-042…MW-055 добавлены под доску MyWork: контракты проекции, Idea Bank, workflow engine, work types, обсуждение и steering, backend проекции, четыре UI-карточки, мастер импорта и приёмка доски. Пересмотрены MW-010, MW-011, MW-029, MW-036, MW-037, MW-041. Сняты MW-027 и MW-035.

Новые карточки **не создаются в legacy-ledger**: их `Board ID` помечен как «не создана», потому что они принадлежат доске MyWork, которой ещё нет. Поэтому `tasks.json` — единственный источник DAG для всего набора v0.2, и именно его проверяет `node .tmp/gen-cards.mjs` (валидатор: циклы, висячие зависимости, расхождение заголовка и `dependsOn` между markdown и JSON).

Карточки и `tasks.json` регенерируются из одного источника; расхождение между ними считается дефектом.

Для coding-карточек закреплены права `workspace-write`; текущий default DSH — `read-only`. Перед первым запуском DSH может запросить штатное подтверждение прав карточки. Оно не выдавалось при подготовке. Full access и автоматическая эскалация не назначены.

Рабочая папка **попадает на GitHub** — прежняя оговорка «на GitHub не попадёт» отменена решением владельца 2026-10-03 (R-54). Внешняя резервная копия при этом остаётся полезной: она спасает от истории, переписанной в репозитории. При подготовке v0.2 (2026-09-16) коммиты и push не выполнялись.
