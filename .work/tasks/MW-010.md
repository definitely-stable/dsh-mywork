Объём:
Подключить подтверждённую версию Beads 1.3.0 через capability-aware адаптер: CLI-only (bd create --graph как атомарный composite с cycle-check, bd batch как одна транзакция, включая dep add и dep remove, bd update --if-status/--if-assignee как guard с exit 13, bd update --claim, bd heartbeat, bd reclaim, bd events tail --since). bd serve не поднимается: HTTP-транспорт остаётся спроектированным, но не построенным портом с capability http=false, поэтому guard expected_version на composite недоступен, и composite с ожидаемой ревизией идёт через staged-мутацию, а не эмулируется. Реализовать get/ready/claim/transition/dependencies/mutatePlan, mapping статусов и приоритетов, reconciliation loop и поведение при outage. Beads владеет task graph; attempts, leases, reviews и git refs остаются в MyWork. Воркспейс уже инициализирован владельцем: .beads в корне репозитория, backend dolt, режим embedded, prefix mw (id вида mw-<hash>), каталог скрыт через .git/info/exclude. Связь карточки с задачей идёт через external_ref вида mw-card:MW-0XX. Адаптер не выполняет bd init и не зависит от Dolt-remote: origin недоступен из этой среды, поэтому bd dolt push/pull вне scope.

Приёмка:
AdapterCapabilityManifest перечисляет http, graph-apply, batch, batch-dep-remove, guarded-batch, metadata-set, events-journal, claim-lease, heartbeat, reclaim, и отсутствующая возможность даёт типизированный отказ, а не эмуляцию. Инверсия приоритета проверена round-trip на 0..4 и на отсутствующем значении (Beads 0 — высший, MyWork — higher first). cancelled и superseded отображаются в frozen-статусы и НЕ удовлетворяют зависимость: зависимый остаётся заблокированным, пока MyWork не потребует явного решения. draft и planned отображаются в wip-статусы и не появляются в bd ready; ready отображается в open. Review находится в wip-категории. Metadata пишется только ключевыми операциями, документная замена не используется. При отсутствии beads-воркспейса адаптер отказывает fail closed и выдаёт точную команду инициализации, не выполняя bd init. Concurrent claim: ровно один выигрывает. Cycle и stale revision отвергаются. Повтор операции идемпотентен. Journal читается курсором и после sync выполняется re-baseline. Адаптер работает на существующем воркспейсе .beads с prefix mw и не создаёт его сам. Готовность читается только из bd ready и bd blocked: поля is_blocked в bd list --json нет ни у одной задачи, включая заблокированные, поэтому опираться на него запрещено. status.custom должен содержать полный набор из ADR023 (десять статусов); неполный набор даёт предупреждение Doctor, а не молчаливую работу. Доказано экспериментом: frozen-блокер оставляет зависимого заблокированным, wip-статусы не появляются в bd ready, единственный ready-статус — open. Контрактные тесты работают на воркспейсе ВНЕ дерева репозитория: bd отказывается создавать вложенный воркспейс, а любая команда из подкаталога репозитория попадает в воркспейс предка. Journal-курсор инвалидируется не только после bd dolt pull, но и при смене Dolt-ветки. Worktree разделяет базу через git common directory discovery, ручной redirect не нужен и не должен появляться. Write-путь проверен под ограниченной песочницей (create/list/delete — exit 0), поэтому недоступность Dolt-корня должна давать ADAPTER_UNAVAILABLE и Doctor-пункт, а не молчаливый повтор. bd init при недоступном Dolt-корне падает паникой (exit 2) вместо чистой ошибки — этот случай обязан распознаваться по exit code и stderr.
