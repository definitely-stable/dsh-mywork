Объём:
Реализовать read-only legacy adapter с preview, выбором карточек и commit, сохранением source ID, истории, execution links и provenance. Источник — файл ledger-v2.json, читаемый напрямую: GET /api/task-board/state используется только пока плагин смонтирован, а после cutover строка web-ui-task-board убирается из профиля, поэтому архив обязан читаться из файла, а не по HTTP. Правило выбора карточек: карточка eligible, если её workspaceId равен workspaceId MyWork И статус не done; в реальном леджере эти два критерия совпадают (6 done-карточек лежат в отдельном воркспейсе 47b14762, 35 незавершённых — в 3fc33afb). Мастер показывает потери и ссылки, находит открытые исполнения и предлагает дождаться завершения либо явно отменить. done-карточки не импортируются и остаются legacy-архивом. Перед cutover проверяется, что legacy autoRunTodo выключен и расписаний на мигрированных карточках нет, иначе проект получит двух исполнителей. Отключение старых запусков и расписаний выполняется только после верифицированного cutover и явного подтверждения.

Приёмка:
Ни одной записи в legacy-ledger: хеш файла до и после мастера совпадает. done-карточки не выбираются и не появляются в колонке «Готово». Открытый execution блокирует commit и предлагает wait либо cancel без автоотмены. Повтор commit идемпотентен по sourceId и не дублирует карточки. Не-MyWork проект не затронут: хеш чужого проекта неизменен. При отсутствии безопасного hook-а доска показывает read-only ссылку и НЕ утверждает, что legacy-scheduler остановлен. Ни одно legacy-исполнение не превращается в Attempt. Архив читается без запущенного legacy-плагина: тест прогоняет preview и открытие архивной ссылки при отсутствующей строке web-ui-task-board. Preview явно показывает карточки, у которых доска и артефакты расходятся (например MW-001 помечен failed, хотя отчёты существуют), и не конвертирует их автоматически. Cutover не начинается, пока legacy autoRunTodo не выключен и на мигрированных карточках нет расписаний. Формы TaskProvenance, LegacySourceRef и ExternalExecutionRef объявлены в контрактах. Импортированная задача имеет origin=imported-legacy, непустые externalExecutions и ноль попыток; ни один attempt id не совпадает ни с одним external execution id; импортированная задача не может стать done без MyWork-review.

Ограничения исполнения: одна карточка за запуск; не переходи к следующей. Используй существующие patterns/DSH API/stdlib, без speculative scaffolding. Сначала узкая проверка, затем расширение по риску. Не запускай субагентов, платные LLM-пробы или другую модель автоматически. Не меняй живой DSH profile, чужие проекты или доску разработки. При неоднозначности поведения, architecture или security задай пользователю короткий вопрос; не выдумывай fallback.
Не выполняй push/merge/publish/release без отдельного запроса. Commit — только если пользователь отдельно поручил; для отчёта достаточно diff и base SHA. Не отмечай работу принятой только по self-review.
