Объём:
Реализовать structured Plan Mutation с baseRevision, create/update/dependencies и классификацией изменений (unchanged, modified, cancelled, superseded, newly-created). Для composite-мутации, которая не выражается одним примитивом Beads (dep_remove вместе с metadata/labels), реализовать staged operation: admission pause, запись staged-записи, раздельное применение, integrity verification и recovery state. Реализовать additive-only классификатор, которым L3 решает, можно ли утвердить план без человека. Worker создаёт WorkProposal и не перестраивает DAG. Плюс производный BlockerResolutionGate: он открыт ровно тогда, когда существует frozen-блокер с неудовлетворённым зависимым, и персистится только решение; действия void, keep-blocking и supersede-dependent. Плюс операторский выход из PLAN_MUTATION_RECOVERY: resume, revert (только для шагов, помеченных обратимыми) и отчёт целостности, доступные и без UI, потому что доска сама может быть недоступна.

Приёмка:
Отклоняются cycles, stale revisions и недопустимые изменения running Task: running task меняется только по явной policy. Composite-мутация с dep_remove проходит через staged: новые admission приостановлены, staged-запись сохранена, при ошибке на середине состояние становится PLAN_MUTATION_RECOVERY и ни один зависимый не стартует, при успехе integrity verification подтверждает отсутствие циклов и целостность DAG до возобновления очереди. Частично невидимого DAG не возникает ни в одном сценарии. additiv-only классификатор возвращает true только для create и dep_add и false при любом update, removal, смене scope или приоритета. Повтор staged не дублирует задачи. Proposal проходит отдельный путь принятия. Отмена блокера с двумя зависимыми даёт гейт ровно на этих двух; void снимает оба ребра через staged и переводит зависимых в ready; keep-blocking оставляет причину в audit; supersede-dependent переводит обоих в superseded; блокер в done гейта не порождает. После kill контроллера в середине применения recovery и пауза admission сохраняются; resume доводит план с пройденной integrity verification; revert восстанавливает прежний набор зависимостей; ни один путь не оставляет частично видимого DAG.
