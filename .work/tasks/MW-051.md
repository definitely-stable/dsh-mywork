Объём:
Создать визуальный редактор WorkflowRevision поверх того же валидатора, что использует engine: типизированные узлы, ветвления, условия, approval gates, bounded retries и human gates. Добавить декларативные правила trigger/condition/action с закрытыми каталогами. Редактор создаёт декларативный документ и не имеет произвольного shell/code escape hatch.

Приёмка:
Редактор не может сохранить документ, который отвергает валидатор, потому что вызывает тот же валидатор. В схеме узла нет поля, способного выразить shell, command, executable или код. Preview показывает diff против frozen revision. Trigger, condition и action берутся из закрытых каталогов, и неизвестное значение отвергается. Срабатывание правила пишет audit с вычисленным условием. Невалидный документ даёт понятную ошибку и не сохраняется.

Ограничения исполнения: одна карточка за запуск; не переходи к следующей. Используй существующие patterns/DSH API/stdlib, без speculative scaffolding. Сначала узкая проверка, затем расширение по риску. Не запускай субагентов, платные LLM-пробы или другую модель автоматически. Не меняй живой DSH profile, чужие проекты или доску разработки. При неоднозначности поведения, architecture или security задай пользователю короткий вопрос; не выдумывай fallback.
Не выполняй push/merge/publish/release без отдельного запроса. Commit — только если пользователь отдельно поручил; для отчёта достаточно diff и base SHA. Не отмечай работу принятой только по self-review.
