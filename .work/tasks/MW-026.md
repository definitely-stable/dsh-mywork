Объём:
Planner получает goal/workspace/current graph, запускается в fresh Session, выдаёт validated Plan Mutation и завершает работу. Task Setter не состоит в Worker pool и не общается с исполнителями; semantic WorkProposal/replan направлять сюда. Плюс роль planner из реестра, модель по ModelPolicy воркспейса, права read-only, выход — artifact planner-dag и структурированный PlanMutation. Planner выдаёт только additive: создание задач и рёбер между новыми; изменение существующей задачи — отдельная ReplanCommand со своим approval, и смешение запрещено типом. Утверждение — предпросмотр структурой (задачи, рёбра, claims, work type, вычисленный класс мутации) с действиями Comment, Approve и Reject; правка плана в UI в объём не входит.

Приёмка:
Невалидный/устаревший output не меняет graph. Planner не выполняет implementation и не остаётся runtime coordinator. Route настраиваемый; тесты fake/keyless, без обязательной frontier модели. Мутация с update существующей задачи отклоняется с PLANNER_SCOPE_DENIED и граф не меняется. Сессия Planner не может писать в workspace. Отклонённый план не оставляет ни задач, ни artifact planner-dag в применённом состоянии.
