## Работа с DeepSeek V4.1 Flash

Одна карточка — одна ограниченная задача. Читать только указанные разделы и связанные файлы. Проверять prerequisites по отчётам/исходникам, а не доверять одному статусу. Не исполнять следующую карточку автоматически. При недостающем контракте или выборе, влияющем на поведение/безопасность, записать blocker и задать владельцу короткий вопрос. Не запускать других агентов и не менять модель без отдельного решения пользователя.

При реализации делать минимальный root-cause diff; готовые patterns/stdlib/DSH API прежде новых зависимостей. Сохранять unrelated dirty work. Проверки сначала узкие; LLM/provider вызовы заменять fakes, пока не требуется разрешённая live-проверка. Платные пробы, push, merge, publish и production действия требуют отдельного запроса. Диагностика и verification не должны переписывать живой профиль DSH, чужой workspace или общую Task Board.

В задаче фиксировать изменённые пути, команды/exit codes, ограничения, base/head при наличии коммита. Отчёт писать в путь из карточки. Code review выполнять отдельной сессией/исполнителем; не считать self-review независимой приёмкой.

## Открытые решения и gates

- MW-001 фиксирует конкретные версии DSH/Cordis/Beads, API и один внешний Memory backend; текущие архитектурные API — проектные контракты, не подтверждение наличия в Host.
- MW-002 выбирает минимальную физическую структуру пакетов и harness проверок на основании установленного SDK.
- Beads claim/plan mutation должны иметь доказанные atomic/idempotent semantics; иначе MW-010/011 blocked. **Уточнено в v0.2**: atomic where backend supports it, staged activation otherwise (ADR023, ADR024); фиктивная атомарность не заявляется.
- **Beads-воркспейс инициализирован владельцем 2026-09-18**: `.beads/` в корне репозитория, backend dolt, режим embedded, база `mw`, prefix `mw` (id вида `mw-<hash>`), каталог скрыт от git через `.git/info/exclude` (`.beads/`, `**/RECOVERY*.md`, `**/SESSION*.md`). `AGENTS.md`, Claude/Codex/Cursor setup и git-хуки не создавались (`--skip-agents --skip-hooks`). Write-путь проверен под ограниченной песочницей: `create`/`list`/`delete` — exit 0. Карточки в `tasks.json` по-прежнему не заводятся в Beads автоматически: их создаёт исполнитель MW-010 по мере готовности.
- **Dolt-remote не является зависимостью.** `bd init` прописал `origin → git+https://github.com/definitely-stable/dsh-mywork.git`, но origin недоступен из этой среды (`schannel: SEC_E_NO_CREDENTIALS`). `bd dolt push/pull` вне scope; sync через remote не заявляется.
- **`bd init` при недоступном Dolt-корне падает паникой** (nil-pointer, exit 2), а не чистой ошибкой. Первый запуск был остановлен ограничением песочницы агента на запись `~/.dolt`; для MW-010 это означает требование распознавать такой отказ по exit code и stderr и выдавать `ADAPTER_UNAVAILABLE` с Doctor-пунктом вместо молчаливого повтора.
- **Решения владельца 2026-09-18**: (1) адаптер CLI-only, `bd serve` не поднимается, HTTP остаётся спроектированным, но не построенным портом; (2) интегратор пишет `Refs: mw-<hash>` в тело коммита; (3) после верифицированного cutover строка `web-ui-task-board` убирается из профиля, а архив читается из файла `ledger-v2.json`, не по HTTP.
- **`status.custom` заполнен частично** (5 из 10 статусов ADR023): заданы `mw_planned:wip, mw_failed:wip, mw_cancelled:frozen, mw_superseded:frozen, mw_in_review:wip`. Вреда нет (некатегоризованный статус тоже исключён из `bd ready`), но полный набор — требование MW-010. Дополнить: `bd config set status.custom "mw_draft:wip,mw_planned:wip,mw_in_review:wip,mw_approved:wip,mw_integrating:wip,mw_changes_requested:wip,mw_failed:wip,mw_needs_attention:wip,mw_cancelled:frozen,mw_superseded:frozen"`.
- **Перед cutover обязательно проверить, что legacy `autoRunTodo` выключен и на мигрированных карточках нет расписаний.** Сейчас он выключен, но 34 backlog-карточки лежат готовыми, и включённый тумблер даст двух исполнителей на один проект.
- Точный ключ claim-TTL в Beads 1.3.0 не детерминирован. MW-010 использует собственный lease MyWork как основной, а `bd reclaim` — только при наблюдаемом TTL (ADR023).
- Установка двух строк (`@dsh-mywork/controller`, `@dsh-mywork/web`) в живой профиль DSH — отдельное решение владельца с подтверждением; при подготовке профиль не меняется.
- Включение `bd events journal` меняет конфигурацию beads-воркспейса и выносится как явное действие владельца; адаптер работает и без него.
- Resident mode, внешняя memory, обучение и security остаются обязательными частями v0.1, а не отложенным MVP.
- MW-039, MW-041 и MW-055 закрывают acceptance только свежими доказательствами; unverified платформа или integration не считается PASS.
