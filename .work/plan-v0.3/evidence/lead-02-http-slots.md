## Опровержения/неожиданное
- «Наследование аутентификации» у `ctx.webServer` отсутствует как механизм: `WebServer` не имеет ни auth-хука, ни middleware — забор пишет сам плагин (`host-routes.ts:150-160`). 403/`forbidden` — контракт плагина, а не харнесса.
- `dsh.client.icon` не существует. `icon` — поле верхнего уровня `package.json` (`P/package.json:5`), и харнесс читает его как base64 data URL в `PluginLocalizedMeta.icon` — `D/packages/util/package-manifest/src/types.ts:44-54`.
- `dsh.client.inject` — это НЕ cordis-inject, а «informational package-name dependencies» для порядка прихода фабрик (`types.ts:84-85`); cordis-сервисы объявляются обычным `export const inject`.
- Живой профиль монтирует доску строкой `@linxin666/dsh-web-all/task-board` с `config.plugin: '@linxin666/dsh-client-ui-task-board'` (`W/cordis.patch.yml:20-35`, `W/node_modules/@linxin666/dsh-web-all/cordis.patch.yml:34-39`) — то есть id клиентской записи здесь `@linxin666/dsh-web-all`, а не имя самого пакета доски.
- Равенство «id панели == ключ main» не рекомендация, а runtime-throw в `selectPanel` (`service.ts:72-77`).

## Не проверено
- HTTP-идентичность `/plugins/<pkg>/client.js` на живом GUI: все пробы (включая ядровой `@deepseek-ai/dsh-client-modules`) дали 404, тогда как `/` дал 401 — слушатель 3080 (`host: 0.0.0.0` + remote-web-ui lanBind, `W/cordis.patch.yml:96-105`) отсекает пути до client-modules, поэтому проба НИЧЕГО не доказывает про id записей. Требуется токен/URL запуска.
- Сохраняется ли состояние контроллера панели при deselect/remount `main` (слот монтируется только у выбранной панели).
- Точная семантика `immediately` на живом шелле (в типах — «boot phase-one barrier», в `manifest.ts:65` — «stage-one prefetch»); `client/web/src/boot.ts:118` фильтрует по нему.
- Стриминг помимо SSE: `registerUpgrade` существует (`D/packages/host/webserver/src/index.ts:181-187`), прецедент им не пользуется.

## Что это значит для плана
1. API: `ctx.webServer.register({ kind:'exact', path:'/api/<ns>/…', handler })` в `ctx.effect`, обязательный `webServer` в `inject`; свой забор (loopback + канонический Host + same-origin маркер) и `403 {ok:false,error:'forbidden'}` как контракт; клиент зовёт путь БЕЗ ведущего слэша.
2. Push — SSE на обычном GET (`text/event-stream`, heartbeat ~15 c, `cache-control: no-store`, unsubscribe по `close`); иначе опрос `GET /state`.
3. Клиент: `dsh.client = { platform:'web' }` + `exports["./client"]`; внешними держать только 9 `PLATFORM_MODULES`, остальное — точными строками в `dsh.client.external`, своё же имя туда не писать; бандл сам регистрируется под голым именем пакета.
4. Панель: `ctx.slots.inject('sidebar.panellist', …)` с `{ id, order, label: () => t(...) }` и `ctx.slots.inject('main', …)` с `key === id`; `order` выбирать в окне 0..10, чтобы встать рядом с Plugins(0)/Schedule(10), не ломая их.
5. View-состояние: либо слот-`store` (получить `PropsStore`: `useStore(selector)` + `actions`), либо собственный контроллер через `inject` — как в прецеденте; персист только через `spec.persist`.
6. Обе регистрации оборачивать в `inject` (шелл может не объявить слот — тогда панель просто отсутствует, boot не падает); ошибки монтирования логировать, не бросать.
