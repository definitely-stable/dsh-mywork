## 3. Опровергнутые утверждения и замена формулировки

### 3.1. (а) «Миграция placement-ключей пустая — board-таблиц нет вовсе» → **BLOCKER в выводе**

Что верно: `grep placement|board` по `packages/storage/**` = 0; 16 `CREATE TABLE` по `packages/*/src`, ни одной placement/board-таблицы; `MYWORK_MIGRATIONS = [OUTBOX_INBOX]` (`storage/src/migrations.ts:91`).
Что опровергнуто: вывод «миграция понадобится только когда MW-047 создаст таблицы, и тогда она пишется сразу в терминах выбранной модели» **не учитывает, что журнал версий общий**. `packages/evidence/src/schema.ts:140` уже занимает `version: 2` (`EVIDENCE_MIGRATIONS`), композиция документирована как `[...MYWORK_MIGRATIONS, ...EVIDENCE_MIGRATIONS]` (`:135`), а `schema_migrations` ключуется `version INTEGER NOT NULL PRIMARY KEY` (`storage/src/migrations.ts:98-99`). Значит `B-12` («новая миграция `version: 2`, `name: 'board-projection'`», тест «`user_version === 2`», гейт «`MYWORK_SCHEMA_VERSION` равен 2») проектирует **коллизию** и закрепляет её тестом.

**Замена формулировки (для `B-12`):** «Новая миграция получает **следующий свободный номер в едином реестре** (`F-18`/`F-19`), а не `2`: версия `2` занята `EVIDENCE_MIGRATIONS` (`packages/evidence/src/schema.ts:140`), а `schema_migrations` ключуется по `version`. Гейт: `board-projection` записана в журнал, её `version` уникален в составе `[...MYWORK_MIGRATIONS, ...EVIDENCE_MIGRATIONS, ...LEASE_MIGRATIONS, ...PLAN_MUTATION_MIGRATIONS]`, таблицы `board_view`/`board_placement`/`board_revision` существуют. Утверждение «`MYWORK_SCHEMA_VERSION === 2`» из гейта **удалить** — это версия только базового списка storage.»

### 3.2. (б) Словарь полос 16→7 — **MAJOR**: с фактическими 16 состояниями согласуется, с D02=C/ADR-030 — нет

С фактическими состояниями (`contracts/task.ts:46-63`) таблица `B-04` сходится идеально: `queue{draft,planned,blocked}` + `ready{ready}` + `active{assigned,executing}` + `review{awaiting-review,reviewing,approved,integrating}` + `error{changes-requested,failed,needs-attention}` + `done{done}` + `closed{cancelled,superseded}` = 16 состояний ровно по одному разу, 7 полос. Инвариант «единственная зона, расщепляемая на две полосы, — `blocked`» тоже верен (`blocked → queue`, `needs-attention → error`, обе в зоне `blocked`/`error`).
Опровергнуто другое: **ADR-030 §3** («`blocked` **и** `needs-attention` → бейдж внутри очереди; `cancelled` и `superseded` → скрытая группа `closed`») и `10-DECISIONS.md:237` (то же) помещают `needs-attention` в очередь, а не в `error`. Объект называет ADR-030 исходом D02=C и одновременно строит словарь, который ему противоречит, ссылаясь на `FINAL-REPORT §9.1` как на источник (`B-04L`, строка «Это ровно та раскладка, которую называет FINAL-REPORT §9.1»).

**Замена формулировки (для `B-04` и `B-04L`):** «Словарь полос: `queue{draft,planned,blocked}`, `ready`, `active`, `review`, `error{changes-requested,failed,needs-attention}`, `done`, `closed{cancelled,superseded}`. **Внимание: это расходится с ADR-030 §3** (`needs-attention` — бейдж внутри очереди). Канон выбирает владелец; до его выбора `B-04` не исполняется, а ADR-030 §3 приводится в соответствие (или словарь — к ADR-030). Правило «зона `blocked` — единственная расщепляемая» сохраняется в обоих случаях.»

1. **Что подставляется в маршрут: имя пакета.** `WebBootEntry.id` — «Entry name == package name» (`packages/client/modules/src/client/manifest.ts:52-54`); запись реестра создаётся как `graphRow(packageName, rev, source.meta)` (`packages/client/modules/src/index.ts:1041`), а URL — `comboReference([id], rev)` (`:483`). Ни `rowId`, ни `moduleName` в маршруте не участвуют: `rowId` — понятие доски, `moduleName` — понятие сборки/лоадера.
2. **Как маршрут связан с `ctx.clientModules`.** Сервис объявлен как `clientModules` (`:620` `super(ctx, 'clientModules')`, объявление в `Context` — `:47`); в активации он ставит на `ctx.webServer` **префикс-маршрут** `/plugins` (`:225`, `:647-653`), а тело ответа собирает из своей таблицы записей (`chunkRequest` `:1080-1098`, `bundleResource` `:1128-1149`). HMR-половина читает тот же сервис (`ctx.clientModules.graph()` — `packages/client/hmr/src/index.ts:162,176`). Манифест клиента (`dsh.client`) на маршрут не влияет — он решает, **станет ли пакет записью вообще** (`modules/src/index.ts:828-848`: без `platform:'web'` — не строка, без `exports['./client']` — throw).
3. **Формы URL.** Запись обслуживается **комбо-ссылкой** `plugins/??<id>/client.js&rev=<rev>` (`comboSearch` `:228-230`, `comboUrl` `:234-235`, `comboReference` `:244-245`) — то есть pathname `/plugins/`, а `<id>/client.js&rev=…` лежит в query. Package-local **чанк** — `/plugins/<id>/<file>?rev=<rev>` (`chunkUrl` `:249-250`) при `CLIENT_CHUNK = /^client\.[A-Za-z0-9][A-Za-z0-9._-]*\.js$/` (`:192`) и точном сравнении `resourceUrl` (`:1094`); всё прочее под `/plugins` → `{status: 404}` (`:1146-1148`). **Голое `client.js` под эту регулярку не подходит** (`node -e` → `client.js -> false`, `client.abc.js -> true`), поэтому `/plugins/<id>/client.js` — 404 **по построению**, а не из-за аутентификации.
4. **Аутентификация.** 401 выдаёт ровно одно место — `BrowserAuth.authorizeIndex` (`packages/client/connection/src/browser-auth.ts:238-275`, текст `:302-310`), то есть **индекс/носитель**; токен запуска — `randomBytes(32)` в `WeakMap` процесса (`:20,52-58`), на диск не пишется; долговечен только секрет подписи cookie (`:12,161-178`). У `ctx.webServer.register` auth-хука нет вовсе (это и утверждал §2.2 этого файла) — значит `/plugins/**` гейтом не покрыт.

**Итог по §8 п.4 (для записи в дельту Lead'ом).** Пункт закрывается **статикой + живой пробой**, и ответ не тот, что предполагала дельта: (а) `<id>` — **имя пакета** клиентской записи (для subpath/агрегатных строк — имя корневого пакета); (б) маршрут принадлежит `ctx.clientModules` и регистрируется префиксом `/plugins` на `ctx.webServer`; (в) запись отдаётся **комбо-формой** `/plugins/??<id>/client.js&rev=<rev>`, а `/plugins/<id>/client.js` — это форма package-local чанка, которая для голого `client.js` не срабатывает **никогда** (`CLIENT_CHUNK`); (г) токен/кука запуска **не нужны**: 401 относится только к индексу/носителю, `/plugins/**` не гейтится; (д) живое доказательство — 200 и тела с `id: "<имя пакета>"` для ядрового, агрегатного и стороннего пакета. Прежний вывод дельты («нужен токен/кука запуска») — **опровергнут**; заодно закрывается триггер (4) D01 (`10-DECISIONS:188`: «платформа начнёт отдавать клиентские модули по иному пути, чем `/plugins/**`… путь на живом GUI не подтверждён») — путь подтверждён, изменилась только форма ссылки.
